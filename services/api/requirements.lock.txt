# EchoB API — festgenagelte Abhängigkeiten
#
# WAS DAS IST. Genau die Versionen, die am 2026-08-26 in Produktion liefen, abgelesen mit
# `pip freeze` im laufenden Container. Der Docker-Build installiert ausschließlich hieraus.
# Damit ergibt jeder Neubau dasselbe Ergebnis wie der letzte — auf demselben Rechner, auf
# einem anderen, heute und in einem halben Jahr.
#
# WARUM AUS DER PRODUKTION ABGELESEN und nicht frisch aufgelöst. Eine frische Auflösung
# hätte neuere Versionen gezogen als die laufenden. Dann wäre das „Festnageln" in Wahrheit
# ein unangekündigtes Upgrade gewesen — das Risiko nicht beseitigt, sondern einmal ausgelöst.
#
# WAS OHNE DIESE DATEI PASSIERTE. `pyproject.toml` deklariert `fastapi>=0.115` ohne
# Obergrenze. Tatsächlich lief 0.141.1 — sechsundzwanzig Minor-Versionen weiter, ohne dass
# es irgendwo stand. Genau so kam FastAPI 0.115 herein und brachte die 204-Antworten zu
# Fall: Die App startete nach einem Rebuild nicht mehr, und niemand hatte etwas geändert.
#
# ─────────────────────────────────────────────────────────────────────────────
# WIE MAN SIE ERNEUERT — bitte regelmäßig, etwa vierteljährlich.
#
# Eine Sperrliste, die niemand zu erneuern wagt, wird selbst zum Sicherheitsproblem: Man
# sitzt dann auf Bibliotheken mit bekannten Lücken. Der Weg ist deshalb kurz gehalten:
#
#   1. Neu auflösen, in einem Wegwerf-Container, gegen die Grenzen aus pyproject.toml:
#        cd services/api
#        docker run --rm -v "$PWD":/w -w /w python:3.12-slim sh -c \
#          "pip install --quiet . && pip freeze --exclude echob-api" > requirements.lock.new
#
#   2. Ansehen, was sich ändert — das ist der eigentliche Prüfschritt:
#        diff requirements.lock.txt requirements.lock.new
#
#   3. Tests gegen den neuen Stand laufen lassen, DANN übernehmen:
#        mv requirements.lock.new requirements.lock.txt
#
# Springt dabei eine Hauptversion, gehört die Obergrenze in `pyproject.toml` bewusst
# angehoben — nicht stillschweigend.
# ─────────────────────────────────────────────────────────────────────────────
#
# `echob-api` selbst steht hier NICHT: Das Anwendungspaket wird im Dockerfile getrennt
# installiert (`pip install --no-deps .`), sonst würde es sich selbst auflösen wollen.
